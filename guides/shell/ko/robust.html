안전한 스크립트

오류가 나면 멈추고, 끝나면 뒷정리를 하고, 무엇을 했는지 기록을 남기는 스크립트를 쓴다.

이 페이지에서 다루는 내용
  • set -euo pipefail
  • set -e가 걸리는 곳과 안 걸리는 곳
  • 따옴표와 cd
  • 예제: 임시 디렉터리에서 ORCA 돌리기
  • ShellCheck
  • Windows 줄바꿈 (CRLF)

set -euo pipefail

bash는 기본적으로 명령 하나가 실패해도 다음 줄로 넘어간다. 입력 파일 복사가 실패했는데 계산을 돌리고, 디렉터리 이동이 실패했는데 엉뚱한 곳에서 rm을 실행한다. 스크립트 맨 위에 다음 줄을 넣으면 이런 일이 줄어든다. 

#!/bin/bash
set -euo pipefail
옵션효과
-e명령이 0이 아닌 종료 코드를 내면 스크립트를 멈춘다
-u정의되지 않은 변수를 쓰면 오류로 멈춘다. 오타 난 변수 이름이 빈 문자열로 넘어가지 않는다
-o pipefail파이프 중간 명령이 실패해도 파이프 전체를 실패로 본다

pipefail이 없으면 파이프의 종료 코드는 마지막 명령의 것이다. 파일 이름이 틀려 grep이 실패해도 tail이 성공했으니 전체가 성공으로 나온다. 

$ e=$(grep "FINAL SINGLE POINT ENERGY" watr.out | tail -n 1); echo "status: $?"
grep: watr.out: No such file or directory
status: 0
$ set -o pipefail
$ e=$(grep "FINAL SINGLE POINT ENERGY" watr.out | tail -n 1); echo "status: $?"
grep: watr.out: No such file or directory
status: 2

set -e가 걸리는 곳과 안 걸리는 곳

set -e는 편하지만 규칙이 단순하지 않다. 처음 쓰면 아래 세 경우에서 스크립트가 말없이 멈춘다.

첫째, grep이 아무것도 못 찾으면 1을 돌려준다. 오류가 아니라 "없음"이라는 정상적인 답인데 -e는 실패로 본다. 

#!/bin/bash
set -e
n=$(grep -c "ERROR" water.out)      # ERROR가 없으면 여기서 끝난다
echo "errors: $n"
$ bash e1.sh
$ echo $?
1

아무 메시지 없이 끝난다. 못 찾는 것이 정상일 수 있는 자리에는 || true를 붙인다. n=$(grep -c "ERROR" water.out || true)로 고치면 errors: 0이 찍힌다.

둘째, ((i++))는 i가 0일 때 1을 돌려준다. (( ))는 안의 값이 0이면 실패로 끝나는데, 후위 증가는 증가 전 값인 0을 내놓기 때문이다. 카운터는 i=$((i + 1))로 쓴다. 

#!/bin/bash
set -e
i=0
((i++))            # 여기서 끝난다
echo "i = $i"

셋째, -u는 인자 없이 부른 스크립트의 $1도 정의되지 않은 변수로 본다. 

$ cat e3.sh
#!/bin/bash
set -u
mol=$1
echo "mol = $mol"
$ bash e3.sh
e3.sh: line 3: $1: unbound variable

인자가 없을 수도 있는 자리에서는 ${1:-}처럼 기본값을 준다. 빈 값이 되고 오류는 나지 않는다. 그다음 [[ -z $mol ]]로 검사해 사용법을 보여 준다.

반대로 -e가 걸리지 않는 곳도 있다. if, while의 조건, &&와 ||의 왼쪽에서는 실패가 무시된다. 함수를 if 조건으로 부르면 그 함수 안 전체에서 -e가 꺼진다. set -e는 안전망일 뿐이고, 중요한 명령은 || exit 1처럼 직접 검사하는 편이 확실하다.

따옴표와 cd

변수는 "$f", 명령 치환은 "$(...)"로 전부 감싼다. 감싸지 않아도 되는 자리를 외우는 것보다 늘 감싸는 편이 빠르다. 예외는 [[ ]] 안과 $(( )) 안 정도다.

cd는 실패하면 현재 위치에 그대로 남는다. 그다음 줄이 rm -f *.tmp라면 엉뚱한 디렉터리의 파일이 지워진다. cd 뒤에는 늘 || exit 1을 붙인다. 

cd "$scratch" || exit 1
rm -f ./*.tmp

프로그램이 있는지는 command -v로 확인한다. 찾으면 경로를 출력하고 0을, 못 찾으면 1을 돌려준다. ORCA를 병렬로 돌릴 때는 전체 경로로 불러야 하므로, 여기서 얻은 경로를 그대로 쓰면 편하다. 

if ! orca_bin=$(command -v orca); then
    echo "error: orca not found in PATH" >&2
    exit 1
fi
같은 이름의 다른 orca

Ubuntu 데스크톱에는 GNOME 화면 낭독기가 /usr/bin/orca로 깔려 있다. ORCA를 PATH에 넣지 않은 채 스크립트를 돌리면 계산 대신 화면 낭독기가 뜬다. type -a orca로 어느 파일이 불리는지 확인하고, ORCA 디렉터리를 PATH 앞쪽에 둔다.

예제: 임시 디렉터리에서 ORCA 돌리기

계산 노드의 로컬 디스크에서 계산하고 출력만 가져오는 스크립트다. 지금까지 나온 방법을 한데 모았다. mktemp -d는 겹치지 않는 이름으로 임시 디렉터리를 만든다. trap '...' EXIT는 스크립트가 끝날 때 정상 종료든 오류로 멈추든 지정한 명령을 실행한다. 여기서는 임시 디렉터리를 지운다. 

#!/bin/bash
# 입력 파일마다 임시 디렉터리에서 ORCA를 돌리고 출력을 원래 위치로 가져온다
set -euo pipefail

dry_run=0
if [[ ${1:-} == "-n" ]]; then
    dry_run=1
    shift
fi

log() {
    printf '[%s] %s\n' "$(date '+%F %T')" "$*"
}

if ! orca_bin=$(command -v orca); then
    echo "error: orca not found in PATH" >&2
    exit 1
fi

scratch=$(mktemp -d "${TMPDIR:-/tmp}/orca.XXXXXX")
trap 'rm -rf "$scratch"' EXIT
start_dir=$PWD

for inp in "$@"; do
    dir=$(dirname "$inp")
    name=$(basename "$inp" .inp)

    if (( dry_run )); then
        log "would run $inp"
        continue
    fi

    log "start $name"
    cp "$inp" "$scratch/"
    cd "$scratch" || exit 1
    status=0
    "$orca_bin" "$name.inp" > "$name.out" || status=$?
    cp "$name.out" "$start_dir/$dir/"
    rm -f "$scratch"/*
    cd "$start_dir"

    if grep -q "ORCA TERMINATED NORMALLY" "$dir/$name.out"; then
        log "done $name"
    else
        log "FAILED $name (exit status $status)"
    fi
done
$ ./run_orca.sh -n */*.inp
[2026-09-29 00:15:54] would run benzene/benzene.inp
[2026-09-29 00:15:54] would run water/water.inp
$ ./run_orca.sh */*.inp
[2026-09-29 00:15:54] start benzene
[2026-09-29 00:15:54] FAILED benzene (exit status 1)
[2026-09-29 00:15:54] start water
[2026-09-29 00:15:54] done water
$ ls -d /tmp/orca.*
ls: cannot access '/tmp/orca.*': No such file or directory

몇 군데를 짚어 둔다.

  • -n을 주면 실제로 돌리지 않고 무엇을 할지만 찍는다. 파일 수백 개를 건드리는 스크립트는 먼저 이렇게 확인한다.
  • "$orca_bin" ... || status=$?는 ORCA가 실패해도 set -e로 스크립트가 멈추지 않게 하면서 종료 코드를 남긴다. 계산 하나가 실패했다고 나머지를 버리지 않는다.
  • log는 줄마다 date '+%F %T' 형식의 시각을 붙인다. 작업 스크립트의 출력 파일에 남으면 어느 계산에 시간이 얼마나 걸렸는지 나중에 알 수 있다.
  • trap이 임시 디렉터리를 지웠기 때문에 마지막 ls에서 아무것도 나오지 않는다.

스케줄러는 작업이 시간 초과로 끝날 때 먼저 SIGTERM을 보낸다. bash가 이 신호로 종료되면서 EXIT trap도 실행된다. 다만 SIGKILL로 강제 종료되면 어떤 trap도 돌지 않는다. PBS와 Slurm 스크립트에서 scratch를 다루는 법은 07장에 있다.

ShellCheck

ShellCheck는 셸 스크립트의 흔한 실수를 찾아 주는 정적 분석 도구다. 웹사이트에 붙여 넣어도 되고, apt install shellcheck이나 conda install -c conda-forge shellcheck로 설치해도 된다. 아래는 이 장에서 다룬 실수가 모인 스크립트다. 

#!/bin/bash
for f in $(ls */*.out); do
    cd $(dirname $f)
    grep "ORCA TERMINATED NORMALLY" $(basename $f)
    cd ..
done

#!/bin/bash
for f in */*.out; do
    (
        cd "$(dirname "$f")" || exit 1
        grep -H "ORCA TERMINATED NORMALLY" "$(basename "$f")"
    )
done

Windows 줄바꿈 (CRLF)

Windows 편집기에서 쓴 스크립트는 줄 끝이 \r\n(CRLF)이다. Linux는 \n만 줄바꿈으로 보므로 \r이 명령이나 경로의 일부로 붙는다. 첫 줄의 shebang에 붙으면 이런 오류가 난다. 

$ ./crlf.sh
bash: ./crlf.sh: /bin/bash^M: bad interpreter: No such file or directory
$ bash crlf2.sh
crlf2.sh: line 2: cd: $'jobs\r': No such file or directory
crlf2.sh: line 3: $'ls\r': command not found

^M과 \r이 같은 글자다. file로 확인하고 sed나 dos2unix로 고친다. 

$ file crlf.sh
crlf.sh: Bourne-Again shell script, ASCII text executable, with CRLF line terminators
$ sed -i 's/\r$//' crlf.sh
$ file crlf.sh
crlf.sh: Bourne-Again shell script, ASCII text executable

dos2unix crlf.sh도 같은 일을 하지만 클러스터에 깔려 있지 않을 때가 있다. sed는 어디에나 있다. Windows에서 VS Code로 편집한다면 오른쪽 아래 상태 표시줄의 CRLF를 눌러 LF로 바꿔 저장한다. Windows에서 옮겨 온 입력 파일이나 목록 파일도 같은 문제를 일으킨다.
