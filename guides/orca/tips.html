팁과 트러블슈팅

계산이 멈췄을 때, 결과가 이상할 때. 매뉴얼 §8을 한국어로 풀어 정리했습니다.

이 페이지에서 다룹니다
  • SCF가 수렴하지 않을 때
  • 최적화가 발산할 때
  • 진동수에 작은 음수가 섞일 때
  • 메모리 부족
  • 병렬이 느릴 때
  • 스핀 오염

SCF가 수렴하지 않을 때

매뉴얼 §8.3은 SCF 수렴 실패가 거의 항상 열린 껍질 상황에서 발생하며, 해결책의 핵심은 “더 나은 초기 궤도(better starting orbitals)”라고 강조합니다. 권장 전략은 다음과 같습니다.

전략 ① — 작은 베이시스로 먼저 수렴

# 1단계: 작은 베이시스 + 느슨한 수렴 + 강한 감쇠
! BP86 def2-SV def2/J SlowConv LooseSCF
%scf
   MaxIter 300
end
* xyzfile 0 3 mol.xyz

$new_job

# 2단계: 1단계의 궤도를 읽고 큰 베이시스로 확장
! BP86 def2-TZVP def2/J MOREAD
%moinp "step1.gbw"
%scf
   GuessMode CMatrix
end
* xyzfile 0 3

$new_job

# 3단계: 목표 함수로 마무리
! B3LYP D4 def2-TZVP RIJCOSX def2/J MOREAD
%moinp "step2.gbw"
* xyzfile 0 3

전략 ② — SOSCF 또는 TRAH 활용

DIIS가 0.001 정도에서 정체될 때는 2차 SCF(SOSCF) 또는 TRAH(Trust-Region Augmented Hessian)를 활성화합니다. 

%scf
   SOSCF      true     # 2차 SCF
   SOSCFStart 0.001    # DIIS 오차가 이보다 작으면 SOSCF로 전환
end
# 가장 어려운 경우의 마지막 수단: TRAH
! B3LYP def2-TZVP TRAH

전략 ③ — 큰 감쇠와 level shift

%scf
   DampFac    0.90    # 큰 감쇠
   DampErr    0.02    # DIIS 오차가 이 값 이하가 되면 감쇠 끔
   Shift shift 0.5 erroff 0 end   # 가상 궤도를 0.5 Eh 만큼 위로 밀어 올림
end

전략 ④ — 연관된 닫힌 껍질에서 시작

홀수 전자 시스템이 잘 수렴하지 않을 때, 양이온이나 음이온의 닫힌 껍질 계산을 먼저 한 뒤 그 궤도를 읽어 오는 방법이 있습니다. 닫힌 껍질은 일반적으로 더 잘 수렴합니다.

수렴 문제의 8할은 좌표

매뉴얼이 직접 언급하듯이, 수렴 실패의 가장 흔한 원인은 “비합리적인 구조”입니다. 결합 길이가 0.5 Å로 짧거나, 두 원자가 같은 위치에 있거나, 단위가 Å이 아닌 bohr인 채로 입력되었거나 하는 경우입니다. 방법을 바꾸기 전에 좌표가 화학적으로 합리적인지 먼저 확인하시기 바랍니다.

최적화가 발산할 때

  1. 최대 step 줄이기: %geom MaxStep 0.1 end (단위 bohr). 진동을 잠재웁니다.
  2. 좌표계 전환: !COpt로 데카르트 좌표를 시도합니다.
  3. 초기 헤시안 강화: 저렴한 방법으로 헤시안 계산 후 InHess Read로 읽어 옵니다. 매뉴얼이 보여 주는 예는 “1단계 NumFreq → 2단계 OptTS” 패턴입니다.
  4. SCF 임계값 강화: 평탄한 표면에서는 SCF 잡음이 그래디언트를 흔듭니다. TightSCF 이상을 권장합니다.
  5. 적분 격자 강화: DefGrid3으로 DFT 격자 정밀도를 올립니다.

진동수에 작은 음수가 섞일 때

허수가 ±10~30 cm⁻¹ 정도의 작은 값이라면 대개 “진짜 음의 곡률”이 아니라 수치 잡음입니다. 다음 순서로 시도해 보시기 바랍니다.

  1. VeryTightSCF DefGrid3로 SCF와 격자 정밀도를 올린 뒤 재최적화 + 재계산.
  2. VeryTightOpt로 최적화 임계값을 강화.
  3. NumFreq CentralDiff true로 양측 차분(시간은 2배가 됩니다).

반대로 큰 허수(수백 cm⁻¹)는 진짜 음의 곡률입니다. 해당 모드의 방향으로 약간 변위를 주어 재최적화하시면 됩니다. orca_pltvib를 활용하면 변위된 좌표를 쉽게 만들 수 있습니다.

메모리 부족

“Please increase MaxCore” 메시지를 마주쳤다면 다음 점들을 점검하시기 바랍니다.

  • %maxcore 값을 늘립니다 (단위 MB). 가용 메모리의 60~70%까지 분배합니다.
  • 병렬 프로세스 수를 줄여 코어당 메모리를 늘립니다.
  • 스크래치 디렉토리($ORCA_SCRDIR)가 충분한 디스크 용량의 빠른 SSD를 가리키는지 확인합니다.
  • 가능하다면 RI 근사(RIJCOSX, RI-JK)를 활성화해 메모리를 절약합니다.
# 클러스터 작업 스크립트에서 스크래치 설정 예
export ORCA_SCRDIR=/scratch/$USER/orca_$$
mkdir -p $ORCA_SCRDIR
cd $ORCA_SCRDIR
orca $SLURM_SUBMIT_DIR/job.inp > $SLURM_SUBMIT_DIR/job.out
cp -r * $SLURM_SUBMIT_DIR/
cd / && rm -rf $ORCA_SCRDIR

병렬이 느릴 때

코어 수를 늘렸는데 속도 향상이 미미하다면 다음을 점검합니다.

  • I/O 병목: 네트워크 디스크에서 실행하면 모든 코어가 같은 디스크를 두드려 느려집니다. 반드시 로컬 디스크(NVMe SSD 이상)를 스크래치로 사용하시기 바랍니다.
  • 과도한 병렬화: RI-DFT는 16코어 이상에서 효율이 떨어집니다. CCSD(T)는 8~16코어가 무난합니다.
  • OpenMPI 통신: 노드 간 통신(infiniband 등)이 없는 경우, 한 노드 안에서만 병렬화하시기를 권합니다.
  • NumFreq, NEB 등 “독립적인 변위·이미지”가 많은 작업은 nprocs_group으로 변위 단위 병렬화를 활용하면 좋습니다.

스핀 오염

UKS/UHF 계산에서 ⟨S²⟩이 이상값에서 벗어나면 “스핀 오염”이 있다고 합니다. 도플렛(S = 1/2)의 이상 ⟨S²⟩는 0.75, 트리플렛(S = 1)은 2.0입니다. 벗어남이 5% 이내라면 무시할 만하지만, 10% 이상이면 결과의 신뢰성이 떨어집니다.

매뉴얼이 권장하는 진단 도구는 !UNO !UCO 조합입니다.

! B3LYP D4 def2-SVP UNO UCO TightSCF

* xyzfile 0 1 mol.xyz

출력의 UCO Overlap 테이블에서 0.85 이하의 오버랩이 보이면 “스핀-커플드 페어”로 해석합니다. 단일항 디라디칼이나 결합이 끊어지는 과정 등에서 자주 나타납니다. 이런 시스템은 일반적으로 단일참조 DFT/HF의 한계 영역으로, 정확한 결과를 원하면 다중참조(CASSCF/NEVPT2) 방법으로 넘어가시는 것이 좋습니다.

상황별 권장 워크플로우

일반 유기 분자의 정밀 자유에너지

  1. r2SCAN-3c Opt Freq로 구조와 깁스 보정을 얻습니다.
  2. DLPNO-CCSD(T)/cc-pVTZ + Extrapolate(3/4,cc) 단일점으로 전자 에너지를 정밀화합니다.
  3. 필요시 SMD로 용매 효과를 더합니다.

전이금속 착물 (3d 금속)

  1. TPSSh D4 def2-TZVP Opt Freq — 메타-GGA 하이브리드가 스핀 상태를 잘 묘사.
  2. 스핀 상태가 미묘하면 같은 방법으로 다른 다중도를 모두 계산해 비교합니다.
  3. UV-Vis는 TDDFT, EPR g-tensor는 !EPRNMR로 추가 계산합니다.

유기 광물리 (UV-Vis, 형광)

  1. 기저 상태: B3LYP D4 def2-TZVP Opt.
  2. 흡수: 위 구조에서 TDDFT NRoots=20.
  3. 형광: %tddft IRoot 1 end !Opt로 S1 최적화 후 다시 TD-DFT.
  4. 전하 이동 의심: CAM-B3LYP 또는 wB97X-V로 재계산하여 비교.

반응 메커니즘

  1. 반응물·생성물을 r2SCAN-3c로 최적화.
  2. !XTB NEB-TS로 빠르게 TS 1차 추정.
  3. DFT 수준으로 OptTS + AnFreq + IRC. 정확히 하나의 허수 모드 확인.
  4. 모든 상태점에 DLPNO-CCSD(T) 단일점 + SMD 보정.
  5. ΔG‡, ΔGrxn 산출.

매뉴얼이 강조하는 일반 원칙

베이시스의 일관성

매뉴얼 §8.2가 강조하듯, 최소 베이시스(STO-3G)나 3-21G 같은 작은 split-valence 기저는 정량적 결과에 부적합합니다. Karlsruhe def2 시리즈를 일관되게 사용하시기를 권합니다. 반응물·생성물·전이 상태 모두 같은 베이시스를 써야 오차가 상쇄됩니다.

DFT는 격자가 정확도의 한계

큰 베이시스(예: def2-QZVPP)로 작업할 때, DFT 적분 격자가 DefGrid2에 머물러 있으면 정확도가 격자 잡음에 묶이게 됩니다. 큰 베이시스를 쓸 때는 DefGrid3으로 격자도 함께 올리시기 바랍니다. 메뉴얼의 표현을 빌리면 “격자로 인한 수치 잡음으로 정확도를 깎아 먹지는 마십시오”.

분산 보정은 거의 무료

D3·D4 보정은 계산 시간을 거의 늘리지 않으면서 정확도를 크게 향상시킵니다. 함수가 분산력을 자체 처리(VV10 내장)하는 경우가 아니라면 거의 항상 활성화하시기를 권합니다.

정상 종료가 곧 정확한 결과는 아닙니다

ORCA TERMINATED NORMALLY 메시지가 보여도 결과가 자동으로 신뢰할 수 있는 것은 아닙니다. (1) SCF 수렴 여부, (2) 최적화 수렴 여부, (3) 진동수가 모두 양수인지(또는 TS는 하나의 허수인지), (4) ⟨S²⟩가 합리적인지, (5) 출력의 WARNING 메시지 등을 반드시 직접 확인하시기 바랍니다.

매뉴얼의 마지막 조언

매뉴얼 §8.2의 끝에 인상적인 한 마디가 있습니다. “컴퓨터가 문제를 푸는 것이 아니라, 사람이 푸는 것입니다. 한두 숫자를 더 정확하게 만들 수 있다고 해서 그것이 우리가 다루는 분자의 화학·분광학을 이해하는 데 곧바로 도움이 되는 것은 아닙니다. 기술적 디테일에 갇혀 본래의 통찰을 놓치는 위험은 실재합니다.” 계산의 정확도를 추구하는 것은 좋지만, 그것이 화학적 통찰을 대체하지는 않는다는 점을 잊지 마시기 바랍니다.
