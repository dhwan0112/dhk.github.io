ORCA란 무엇인가

ORCA는 1995년경 Frank Neese 교수가 전이금속 착물의 분광학적 특성을 계산하기 위해 Turbo Pascal로 작성한 작은 준경험적(semi-empirical) 프로그램에서 출발했습니다. 이후 30년 가까이 발전을 거듭해, 지금은 전 세계 약 7만 명의 학술 사용자가 활용하는 대형 패키지로 자리잡았습니다. 버전 6.0(2024)은 사실상 코드 전체를 재설계한 이정표적 릴리스로, SHARK 적분 엔진과 COSX 근사를 중심으로 성능이 크게 개선되었습니다.

ORCA가 다른 양자화학 프로그램과 구분되는 강점은 다음 세 가지로 요약할 수 있습니다. 첫째, 전이금속 화학과 분광학에 특화된 다양한 방법(CASSCF, NEVPT2, DLPNO-CCSD(T) 등)이 잘 구현되어 있다는 점. 둘째, 학술용으로 무료라는 점. 셋째, 적극적인 사용자 커뮤니티가 운영되는 공식 포럼이 있다는 점입니다.

설치 확인

ORCA는 공식 포럼(orcaforum.kofo.mpg.de)에서 학술용 계정으로 회원 가입 후 다운로드할 수 있습니다. Linux, macOS, Windows 바이너리가 제공되며, 본 가이드에서 다루는 모든 예제는 5.0.2, 5.0.4, 6.0.0에서 동작합니다.

설치 후 가장 먼저 확인해야 할 것은 orca 실행 파일이 PATH에 잡혀 있는지입니다. 터미널에서 다음을 실행하면 ORCA 실행 파일의 위치가 출력되어야 합니다. 

# 설치 위치 확인
which orca
병렬 실행 시 절대 경로 필수

병렬 계산을 사용할 때는 ORCA 바이너리의 절대 경로가 PATH에 등록되어 있어야 합니다. which orca로 절대 경로를 확인한 뒤 export PATH=/path/to/orca:$PATH 형식으로 명시적으로 추가하시기 바랍니다. 상대 경로나 별칭(alias)으로는 OpenMPI가 병렬 실행 파일을 찾지 못해 실패합니다. 그리고 OpenMPI 동적 라이브러리를 위해 LD_LIBRARY_PATH도 함께 설정해 주시는 것이 안전합니다.

첫 실행 — H2O 단일점 에너지

ORCA 입력 파일은 단순한 ASCII 텍스트입니다. 확장자는 보통 .inp를 씁니다. 물 분자 한 개의 단일점 에너지를 B3LYP/def2-SVP 수준에서 계산해 보겠습니다. 

# my_first.inp — 물 분자 단일점 에너지
! B3LYP def2-SVP

* xyz 0 1
  O   0.000000   0.000000   0.119262
  H   0.000000   0.763239  -0.477047
  H   0.000000  -0.763239  -0.477047
*

이 입력의 구조를 짧게 짚으면 다음과 같습니다. 더 상세한 설명은 02. 입력 파일 구조에서 다룹니다.

  • !로 시작하는 줄은 키워드 라인입니다. 방법(B3LYP)과 베이시스 세트(def2-SVP)를 지정했습니다.
  • *로 둘러싼 블록은 좌표 입력부입니다. xyz는 데카르트 좌표를, 0 1은 총 전하 0과 다중도 1(닫힌 껍질)을 의미합니다.
  • #으로 시작하는 줄은 주석으로 간주됩니다.

이 파일을 다음과 같이 실행합니다.

# Linux / macOS
orca my_first.inp > my_first.out

# Windows (명령 프롬프트)
orca my_first.inp > my_first.out
출력 리디렉션은 필수입니다

ORCA는 모든 결과를 표준 출력(stdout)으로 내보냅니다. 반드시 > output_file로 리디렉션해 두어야 합니다. 그렇지 않으면 결과가 화면을 스쳐 지나가 사라집니다.

정상적으로 종료되면 출력 파일 마지막에 다음과 같은 문구가 나타납니다. 

FINAL SINGLE POINT ENERGY       -76.419773234567

                            ****ORCA TERMINATED NORMALLY****

FINAL SINGLE POINT ENERGY 줄에 적힌 값이 우리가 얻은 에너지(Hartree 단위)입니다. 위 메시지가 보이면 일단 계산은 성공적으로 끝났다고 볼 수 있습니다.

정상 종료 ≠ 결과의 신뢰성

매뉴얼에서도 강조하듯, ORCA TERMINATED NORMALLY가 출력되더라도 결과가 항상 신뢰할 수 있는 것은 아닙니다. 예를 들어 구조 최적화가 수렴에 실패한 채 최대 반복 횟수에 도달한 경우에도 이 문구는 나타납니다. 실제로 작업이 의도대로 수렴했는지는 항상 출력 파일 전체를 직접 확인하셔야 합니다.

출력 파일과 임시 파일

ORCA를 실행하면 입력 파일과 같은 위치에 여러 부가 파일이 생성됩니다. 주요 파일은 다음과 같습니다.

파일설명
basename.out표준 출력을 리디렉션한 파일. 사람이 읽는 주 결과물.
basename.gbw이진 형식의 분자 궤도 파일(Geometry-Basis-Wavefunction). 재시작이나 후속 계산의 입력으로 쓰입니다.
basename.xyz최적화된 구조의 데카르트 좌표 파일.
basename_trj.xyz최적화 과정의 모든 중간 구조를 담은 trajectory.
basename.engrad에너지와 그래디언트가 저장된 텍스트 파일.
basename.hess진동수 계산 시 생성되는 헤시안 파일.
basename.property.txt각종 분자 특성(쌍극자, 분극도 등)을 정리한 파일.
basename.*.tmp임시 파일들. 정상 종료 시 자동 삭제됩니다.
비정상 종료 후 정리

ORCA가 비정상적으로 종료되면 .tmp 파일들이 남습니다. 다음 실행 전에 정리하는 것이 좋습니다. 

rm basename*.tmp     # Linux/macOS
del basename*.tmp    # Windows

병렬 실행

ORCA는 OpenMPI(Linux·macOS) 또는 MS-MPI(Windows)를 사용해 병렬 계산을 수행합니다. 코어 개수는 두 가지 방식으로 지정할 수 있습니다. 

# 방법 1: 단순 키워드 (PAL2 ~ PAL64 지원)
! B3LYP def2-SVP PAL8

# 방법 2: %pal 블록 (임의의 정수)
%pal
   nprocs 12
end

매뉴얼이 제시하는 실용적인 가이드는 다음과 같습니다.

  • RI-DFT: 16개 코어까지 효율이 잘 나옵니다. 그 이상은 오버헤드가 커집니다.
  • 하이브리드 DFT, HF: 16~24개 코어까지 시도해 볼 만합니다.
  • Coupled-cluster: 보통 8~16개 코어가 무난합니다.
  • 수치 미분(NumFreq, NumGrad): 변위 개수가 많아 코어를 많이 활용할 수 있습니다. 6 × 원자 수 × (4~8)배까지 시도해 볼 수 있습니다.

또한 ORCA 6에서는 변위 단위로 병렬화를 세분화할 수 있는 기능이 추가되었습니다. 예컨대 32개 프로세스를 “4개 프로세스 × 8 그룹”으로 나누어 동시에 여덟 개의 변위를 처리하는 식입니다. 

%pal
   nprocs       32  # 전체 프로세스 수
   nprocs_group  4  # 한 변위에 투입할 프로세스 수
end

메모리 설정

상관 계산 모듈(MP2, CCSD, MRCI 등)은 큰 스크래치 배열을 필요로 합니다. 이를 위해 코어 하나당 사용할 메모리를 %maxcore로 지정해야 합니다. 단위는 메가바이트(MB)입니다. 

# 코어당 4 GB 메모리 (총 사용량 ≈ nprocs × maxcore)
%maxcore 4000
메모리 부족 오류

계산 도중 “Please increase MaxCore”라는 메시지와 함께 SCF가 중단된다면, 물리 메모리에 여유가 있는 한도 안에서 %maxcore 값을 늘리시면 됩니다. 다만 이 값은 “주된 작업 영역”만 가리키므로, 실제 메모리 사용량은 이보다 더 큽니다. 가용 메모리의 60~70% 정도를 분배하는 것이 안전합니다. 예컨대 64 GB 메모리에 8 코어 병렬이라면 %maxcore 5000 정도로 시작하시기를 권합니다.

여기까지가 ORCA 첫 실행의 기본기입니다. 다음 장에서는 입력 파일의 문법을 본격적으로 다룹니다.
